## Regras de personalização

### Disponibilidade semanal

- **Menos de 5 horas:** estenda os prazos e priorize os fundamentos e entregáveis essenciais.

### Experiência

- **Zero:** explique conceitos com mais didática e reforce os fundamentos.
- **Iniciante:** equilibre teoria e prática, consolidando o que a pessoa já conhece.
- **Alguma experiência:** identifique lacunas e priorize prática, portfólio e aprofundamento.

### Objetivo

- **Primeiro emprego:** enfatize portfólio, currículo, entrevistas e candidaturas.
- **Transição:** destaque habilidades transferíveis e projetos que conectem a experiência anterior à nova área.
- **Crescimento:** priorize aprofundamento técnico, responsabilidades avançadas e próximos passos na carreira.

# Roadmap de Desenvolvimento de Software — 120 dias

Plano de estudos para quem está começando do zero e quer se preparar para uma primeira oportunidade em desenvolvimento de software. O foco é **Python, desenvolvimento front-end, SQL, Git e GitHub**, com prática contínua por meio de um projeto de portfólio.

> **Disponibilidade sugerida:** 18 horas por semana  
> **Ritmo:** 6 dias de estudo, aproximadamente 3 horas por dia, e 1 dia de descanso ou revisão leve  
> **Objetivo:** construir fundamentos, publicar a evolução no GitHub e entregar uma aplicação web funcional

## Objetivos de aprendizagem

- Aprender a versionar o próprio trabalho com Git e compartilhar projetos pelo GitHub desde o primeiro dia.
- Desenvolver lógica de programação e aplicações simples em Python.
- Criar interfaces web com HTML, CSS e JavaScript.
- Consultar e modelar dados com SQL.
- Construir uma aplicação web com Flask e SQLite.
- Documentar, testar e apresentar um projeto de portfólio.
- Preparar-se para entrevistas e começar a se candidatar a vagas júnior ou de estágio.

## Tecnologias e ferramentas

- **Versionamento:** Git e GitHub
- **Programação:** Python e JavaScript
- **Web:** HTML, CSS e Flask
- **Banco de dados:** SQL e SQLite; PostgreSQL como conteúdo complementar
- **Ferramentas:** Visual Studio Code, terminal e pytest
- **Opcional, depois do projeto principal:** React, deploy e funcionalidades avançadas

## Como usar este roadmap

1. Crie um repositório no GitHub para registrar exercícios e projetos.
2. Siga os tópicos em ordem, adaptando os dias se algum assunto precisar de mais prática.
3. Faça commits pequenos e descritivos ao concluir etapas.
4. Registre dúvidas e tarefas em issues ou em uma lista no repositório.
5. Priorize entender os fundamentos e concluir a aplicação essencial; os extras são opcionais.

O cronograma representa **120 dias corridos**: 17 semanas completas e um dia final de entrega. Os dias 7, 14, 21 e assim por diante são destinados ao descanso, sem estudo obrigatório. A carga prevista é de aproximadamente 309 horas, contando a sessão final do dia 120.

## Roadmap de 120 dias

### Semana 1 — GitHub primeiro e ambiente

- Criar ou organizar o perfil do GitHub e habilitar a autenticação segura.
- Instalar e conhecer o VS Code, Python, Git e o terminal.
- Criar o repositório `estudos-desenvolvimento` com um README inicial.
- Praticar `git status`, `git add`, `git commit`, `git push` e `git log`.
- Aprender a clonar o repositório e sincronizar alterações com `git pull`.
- Usar issues ou checklists para acompanhar o plano.

**Entrega:** repositório público com apresentação, objetivo de estudos e primeiros registros. Nunca publique senhas, tokens ou dados pessoais.

### Semana 2 — Python: primeiros passos

- Executar programas e entender erros básicos de sintaxe.
- Estudar variáveis, nomes claros, tipos e conversões.
- Usar `input`, operadores aritméticos e comparações.
- Praticar com calculadora, conversor de temperatura e pequenos exercícios.
- Registrar no README como executar os scripts.

**Entrega:** primeiros exercícios em Python publicados no GitHub.

### Semana 3 — Lógica e decisões

- Decompor problemas em entradas, processamento e saídas.
- Estudar `if`, `elif`, `else` e condições compostas.
- Validar entradas e usar operadores lógicos.
- Praticar laços `for` e `while`, contadores e acumuladores.
- Resolver desafios pequenos e explicar a lógica usada.

**Entrega:** conjunto de exercícios com soluções e instruções.

### Semana 4 — Estruturas de dados e funções

- Trabalhar com strings, listas e dicionários.
- Representar dados, como uma tarefa, usando campos nomeados.
- Criar funções com parâmetros e valores de retorno.
- Conhecer escopo, módulos e imports.
- Refatorar exercícios para deixar o código organizado.

**Entrega:** mini projeto de terminal dividido em funções.

### Semana 5 — Python aplicado

- Ler e gravar arquivos; conhecer JSON para dados simples.
- Tratar erros com exceções específicas.
- Criar ambientes virtuais e instalar pacotes com `pip`.
- Praticar comprehensions básicas.
- Criar um pequeno organizador de tarefas no terminal.

**Entrega:** aplicação simples que lista e atualiza tarefas, com limitações documentadas.

### Semana 6 — HTML e CSS

- Estruturar páginas com HTML semântico.
- Usar links, imagens, listas e texto alternativo.
- Criar formulários com labels e tipos de campo adequados.
- Estudar seletores CSS, cascata, tipografia, cores e espaçamento.
- Montar layouts com flexbox.

**Entrega:** página pessoal ou protótipo estático do organizador de tarefas.

### Semana 7 — Responsividade e Git

- Criar layouts mobile-first com media queries.
- Usar CSS Grid para organizar cartões e conteúdos.
- Revisar contraste, foco e navegação por teclado.
- Criar branches, comparar alterações e praticar merge.
- Publicar a página estática, usando GitHub Pages se for adequado.

**Entrega:** página responsiva e repositório com README e captura de tela.

### Semana 8 — JavaScript básico

- Usar o console do navegador para executar e depurar código.
- Estudar `let`, `const`, tipos, operadores e conversões.
- Praticar condições, loops e funções.
- Trabalhar com arrays e objetos.
- Comparar conceitos de JavaScript com o que já foi aprendido em Python.

**Entrega:** exemplos pequenos de JavaScript publicados no repositório.

### Semana 9 — DOM e interface interativa

- Selecionar elementos da página e alterar conteúdo com JavaScript.
- Responder a eventos e submeter formulários.
- Validar dados e apresentar mensagens úteis.
- Adicionar, editar e remover itens da interface.
- Conhecer `localStorage` e entender suas limitações.

**Entrega:** protótipo interativo do organizador de tarefas.

### Semana 10 — SQL essencial

- Entender tabelas, linhas, colunas e tipos de dados.
- Consultar dados com `SELECT` e filtrar com `WHERE`.
- Praticar `LIKE`, `NULL`, `ORDER BY` e `LIMIT`.
- Inserir, atualizar e excluir registros.
- Usar uma chave primária para identificar cada registro.

**Entrega:** esquema inicial da tabela de tarefas e consultas de exemplo.

### Semana 11 — SQL relacional

- Conhecer chaves estrangeiras e relações entre tabelas.
- Consultar dados relacionados com `JOIN`.
- Agrupar e resumir dados com `GROUP BY` e funções de agregação.
- Aplicar restrições e noções básicas de normalização.
- Desenhar o modelo de dados do projeto.

**Entrega:** modelo de banco documentado e consultas para perguntas reais do projeto.

### Semana 12 — Flask e HTTP

- Entender requisição, resposta, URL e métodos HTTP.
- Criar um ambiente virtual e instalar Flask.
- Implementar rotas e respostas simples.
- Renderizar páginas com templates Jinja.
- Receber e validar dados enviados por formulários.

**Entrega:** estrutura inicial da aplicação Flask, com instruções para executar localmente.

### Semana 13 — Flask e SQLite: CRUD

- Definir o esquema SQLite para as tarefas.
- Conectar Flask ao banco e usar consultas parametrizadas.
- Implementar criação e listagem de tarefas.
- Implementar edição e conclusão.
- Implementar exclusão e tratar registros inexistentes.
- Confirmar que os dados continuam disponíveis após reiniciar a aplicação.

**Entrega:** operações principais de cadastro, consulta, atualização e exclusão funcionando.

### Semana 14 — Validação e testes

- Validar dados no servidor e definir regras de negócio simples.
- Apresentar erros e feedback de forma clara.
- Escrever testes básicos com pytest.
- Testar entradas inválidas e outros casos de borda.
- Revisar configuração e garantir que segredos não sejam versionados.

**Entrega:** testes básicos e instruções para executá-los.

### Semana 15 — Integração full-stack

- Conectar o formulário da interface ao back-end e ao banco.
- Exibir tarefas persistidas e adicionar filtros simples.
- Integrar edição, conclusão e exclusão.
- Revisar labels, foco, mensagens e estados vazios.
- Testar manualmente os fluxos completos e corrigir problemas.

**Entrega:** aplicação integrada de ponta a ponta.

### Semana 16 — Acabamento do portfólio

- Revisar o layout em diferentes tamanhos de tela.
- Melhorar semântica, acessibilidade e consistência do código.
- Completar o README com objetivo, tecnologias, instalação e uso.
- Documentar o banco, os testes, as funcionalidades e as limitações.
- Incluir capturas de tela ou uma demonstração.
- Conferir links e arquivos antes de deixar o repositório público.

**Entrega:** versão demonstrável e documentação reproduzível.

### Semana 17 — Entrevistas e busca de vagas

- Preparar uma apresentação pessoal curta e verdadeira.
- Treinar a explicação do projeto, da arquitetura e das decisões.
- Revisar Python, front-end, SQL, Git e GitHub.
- Preparar currículo inicial e organizar o perfil do GitHub.
- Pesquisar requisitos recorrentes em vagas júnior ou de estágio.
- Fazer uma simulação de entrevista e iniciar candidaturas.

**Entrega:** materiais de candidatura e uma lista de próximos tópicos a estudar.

### Dia 120 — Entrega final

- Revisar o README, os testes, a demonstração, os links e a segurança do repositório.
- Registrar o que aprendeu, os desafios encontrados e os próximos passos.
- Iniciar ou continuar candidaturas a vagas compatíveis com seu nível.

## Projeto de portfólio

### Organizador de tarefas de estudo

Aplicação web para cadastrar tarefas, organizá-las por matéria ou prioridade e acompanhar o status de conclusão.

**Stack sugerida**

- Interface: HTML, CSS e JavaScript.
- Back-end: Python com Flask.
- Persistência: SQLite.
- Testes: pytest para os fluxos principais.

**Modelo inicial de tarefa**

- `id`: identificador único.
- `titulo`: campo obrigatório.
- `descricao`: campo opcional.
- `materia`: categoria ou área de estudo.
- `prioridade`: nível definido pelo usuário.
- `status`: por exemplo, pendente ou concluída.
- `data_criacao`: data de criação.

**Critérios de aceite**

- Permite criar, listar, editar, concluir e excluir tarefas.
- Mantém os dados após fechar e reiniciar a aplicação.
- Valida campos e mostra mensagens claras para erros.
- Tem layout utilizável em telas pequenas.
- Inclui instruções reproduzíveis para instalação, execução e testes.
- Está documentada em um repositório GitHub organizado.

**Extras opcionais, depois de concluir o essencial:** busca, filtros adicionais, PostgreSQL, publicação on-line ou React. Não deixe esses extras atrasarem a primeira versão funcional.

## Git e GitHub durante os estudos

- Faça commits pequenos, com mensagens que descrevam a mudança.
- Exemplo: `Adiciona cadastro de tarefas`.
- Use branches para experimentar melhorias sem misturá-las imediatamente à versão principal.
- Atualize o README quando mudar a forma de executar o projeto.
- Use issues para dividir o trabalho em tarefas.
- Não versione tokens, senhas, arquivos de ambiente ou dados pessoais.
- Mantenha no perfil os projetos que você consegue explicar e demonstrar.

## Preparação para entrevistas

### “Por que você quer trabalhar com desenvolvimento?”

Explique sua motivação de forma autêntica e relacione-a ao que está aprendendo. Por exemplo: “Estou estudando Python, front-end e SQL e aplicando esses fundamentos no meu organizador de tarefas. Busco uma oportunidade júnior ou de estágio para contribuir e continuar aprendendo.”

### “Conte sobre um projeto seu.”

Apresente o problema, a solução, as tecnologias, uma decisão técnica, um desafio que enfrentou e o que faria em seguida. Seja transparente sobre o que já está implementado.

### “Como você investiga um erro?”

Explique como reproduz o problema, lê a mensagem de erro, reduz o caso, verifica hipóteses e testa a correção para evitar regressões. Use um exemplo real do seu projeto.

### “O que é uma chave primária?”

É um valor que identifica uma linha de forma única. No organizador, o identificador permite encontrar e atualizar uma tarefa específica.

### “Qual é a diferença entre HTML, CSS e JavaScript?”

HTML estrutura o conteúdo, CSS controla sua apresentação e JavaScript adiciona comportamento e interatividade no navegador.

### “Como você usa Git e GitHub?”

Git registra alterações e commits no projeto; GitHub hospeda o repositório e permite compartilhar o código e colaborar usando recursos como branches e pull requests.
